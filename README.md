# Taste Clash

Веб-приложение, которое сравнивает музыкальные вкусы двух людей по их Spotify и показывает
подробную аналитику совместимости.

**Что показывает**

- Итоговый балл совместимости 0–100% и вердикт («Музыкальные близнецы» … «Параллельные вселенные»)
- Из чего складывается балл: общие исполнители, общие треки, жанры, эпохи
- Общих исполнителей и треки с местами в топе у каждого
- **Диаграмму Эйлера–Венна** по жанрам и по исполнителям: площади пропорциональны числу элементов,
  а каждая область раскрывается в «жанровое дерево» (семья → микрожанры)
- **Radar Chart** в двух режимах: доли жанровых семей и привычки слушателя
  (мейнстрим, разнообразие, постоянство, фокус на любимцах, новизна, explicit)
- **Hipster Index** = 100 − средняя `popularity` исполнителей: шкала андерграунд ↔ мейнстрим,
  распределение топа по популярности и самый нишевый артист у каждого
- Распределение любимой музыки по десятилетиям
- Рекомендации друг для друга — любимцы одного, которых нет в топе у другого
- Текстовые инсайты («Алекс слушает музыку в среднем на 4 года старше»)

**ИИ-разбор (Claude)**

- **Компромиссный вердикт**: «Вам лучше не ездить вместе на машине, но вы сойдётесь на треках X и Y» —
  треки X и Y модель выбирает только из ваших реальных топов (сервер отбрасывает выдуманные id)
- **Микс-плейлист**: треки обоих по очереди, общие треки — мосты между жанрами,
  у каждого трека — фраза, почему он идёт после предыдущего. Список можно скопировать,
  а каждый трек открывается в Spotify

Spotify API не отдаёт число прослушиваний, поэтому «частота» в радаре и весах оценивается
по местам в топах за три периода.

## Как это устроено

Бэкенда нет. Вход — Spotify Authorization Code + PKCE прямо в браузере, токен живёт только в памяти.
Приложение берёт топ-50 исполнителей и треков за три периода (4 недели / 6 месяцев / всё время),
сводит их в «слепок вкуса» с весами и упаковывает в компактный код (deflate + base64url).

- **Ссылка-приглашение** `#invite=<код>` — друг открывает её, входит в свой Spotify и сразу видит результат.
- **Ссылка на результат** `#clash=<код>.<код>` — готовое сравнение пары, без входа.
- **Один экран** — второй игрок подключается на том же устройстве (в окне Spotify «Не вы?»).
- **Демо** — `#demo` или кнопка на главной, работает без Client ID.

Код лежит во фрагменте URL (после `#`), поэтому не попадает в логи серверов.
В нём только имя, аватар и топы — никаких токенов.

**ИИ** работает через небольшой серверный прокси (`server/ai.ts`): ключ Claude API живёт только на сервере.
Браузер отправляет обезличенную сводку — статистику различий и названия треков, а имена людей
заменены на `{A}`/`{B}` и подставляются обратно уже в браузере. Ответ модели проходит через
структурированный вывод (zod-схемы в `server/schema.ts`). На сервере есть лимит —
10 AI-запросов с одного IP за 10 минут — и ограничение размера запроса.
Модель — Claude Opus 5.5 с серверным fallback при отказе (`fallbacks: "default"`).

## Запуск

```bash
npm install
cp .env.example .env.local   # впишите SPOTIFY_CLIENT_ID и ANTHROPIC_API_KEY
npm run dev                  # http://127.0.0.1:5173 — фронт и AI-эндпоинты
```

Продакшен — один Node-процесс (Node ≥ 22.18, TypeScript исполняется без сборки):

```bash
npm run build && npm start   # http://127.0.0.1:8080, PORT/HOST — через переменные окружения
```

Без `ANTHROPIC_API_KEY` всё, кроме ИИ-разбора, работает как раньше; фронт можно выложить
и на статический хостинг — тогда блок ИИ покажет подсказку о настройке.

Настройка приложения в [Spotify Developer Dashboard](https://developer.spotify.com/dashboard):

1. Create app → API: **Web API**.
2. Redirect URI: `http://127.0.0.1:5173/` (Spotify не принимает `localhost` — только `127.0.0.1`;
   для продакшена — ваш HTTPS-адрес).
3. Скопируйте Client ID в `.env.local`. Client Secret не нужен.
4. Пока приложение в **Development Mode**, войти смогут только аккаунты,
   добавленные в *User Management* (иначе API вернёт 403).

Ограничения Spotify Web API для приложений в Development Mode со временем ужесточаются, и часть полей
(жанры исполнителей, popularity) может не приходить. Приложение к этому готово: компоненты без данных
помечаются «нет данных», а балл пересчитывается по оставшимся.

## Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер (с AI-эндпоинтами) |
| `npm run build` | проверка типов + production-сборка в `dist/` |
| `npm start` | production-сервер: `dist/` + `/api/*` |
| `npm test` | unit-тесты модели совместимости и кодека |

## Структура

```
src/lib/spotify.ts   PKCE-вход и загрузка топов
src/lib/profile.ts   сведение трёх топов в взвешенный профиль
src/lib/codec.ts     упаковка профиля в код для ссылки
src/lib/compare.ts   модель совместимости, жанровые семьи, ДНК, инсайты
src/lib/demo.ts      синтетические профили для демо
src/lib/ai.ts        обезличенные запросы к ИИ и подстановка имён
src/components/      лобби, результаты, графики (радар, Венн, парные столбцы), ИИ-панель
server/ai.ts         AI-эндпоинты /api/verdict и /api/mix: валидация, лимиты, вызов Claude
server/schema.ts     zod-контракт запросов и ответов (общий для клиента и сервера)
server/index.ts      production-сервер
```

## Как считается балл

| Компонент | Вес | Метрика |
|---|---|---|
| Исполнители | 35% | косинус векторов близости (топ исполнителей + исполнители любимых треков), насыщение `1 − e^(−5x)` |
| Треки | 15% | косинус векторов треков, насыщение `1 − e^(−8x)` |
| Жанры | 30% | 0.4 × косинус микрожанров + 0.6 × косинус жанровых семей |
| Эпохи | 20% | пересечение гистограмм по десятилетиям, нормированное |

Насыщение нужно, потому что даже у близких по вкусу людей сырой косинус по исполнителям редко выше 0.3–0.4.
Если компонент недоступен, его вес перераспределяется между остальными.
